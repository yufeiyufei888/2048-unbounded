⚠️ 这一版最大的技术发现：评估函数「退化」
早期引擎用 数值 × 位置指数权重（如 2^e × 4^(15-k)）打分， 动态范围高达 4¹⁵ ≈ 10⁹。实测一个左上角的 256 就贡献了全部得分的 75%； 而「某一行两个小块该左靠还是右靠」的差异只占总分的 1.3×10⁻⁴。 搜索对这种量级的差异几乎不敏感 → 除了死保那个大块，其它决策近似随机 → 盘面结构必然崩坏。

早期小样本曾得到「底数越大越差」的误判，但新的多进程复测修正了这个结论：在当前 BitBoard、LUT、limit=6、depth=5 配置下，base=4.5 的 96 局结果为均分 79,514、最高 176,564，明显优于 base=4.0 的同期基线；base=4.25 与 4.75 则分别回落到约 63,881 与 66,562。

因此当前 v7.1 采用 base=4.5，但结论仍需更大样本复核，且尚未证明能稳定突破 16384。v6 换成「排序式评估」——奖励方块沿蛇形路径单调递减，每格贡献都是 O(1) 量级， 结构信息不再被单个大块淹没。单局步数从 ~400 步升到 ~950 步，并打出 2048。

五、v7 追因记：一个把均分砍掉 8 倍的「共享缓冲」

v7 的目标是把 v3 的强结构约束（指数蛇形权重）搬到 v6 的无分配极速内核上。但移植后 均分只有 3,782，且速度异常地快（346 局/分）。
🔍 排查过程（每一步都排除了一个假设）
  • 验证转置表 key 算术 —— 当时判断「无碰撞」（2026-09-15 交接复测证明该结论有误，见第八节）。
  • 禁用转置表重跑 —— 依然崩盘，排除 TT。
  • 12 万次随机棋盘差分测试 moveDir 四个方向 —— 零错误，排除移动逻辑。
  • 2 万个随机局面比对 evaluate 与 v3 的逐格实现 —— 零差异，排除评估函数。
  • 统计搜索树：每步只访问 1,030 节点（v3 是 2,325），每步少一半。

真正的根因：为省内存，空位列表用了一个全局复用缓冲 EMPTY_IDX。而 exitimax 的随机分支这样采样：

for (i = 0; i < n; i++) { const idx = EMPTY_IDX[rand * nEmp | 0]; … 递归 … }

第 2 次迭代时，上一轮递归已经把 EMPTY_IDX 覆盖成子节点的空位列表了。 于是循环读到的索引里混进了「原本已经有方块的格子」，把新方块 OR 到脏格子上 —— 搜索用的棋盘从内部就被破坏了，深层评估全乱，AI 于是乱走、250 步就满盘。

修复：进循环前先把空位快照到按深度索引的局部缓冲。一行改动，均分 3,782 → 30,750（8×），每步节点 1,030 → 1,969。

教训：用全局缓冲加速递归搜索时，任何「跨递归调用」的数据都必须先落快照； 这类 bug 不会报错、不会崩，只会安静地把棋力砍掉一个数量级。

六、踩过的坑（都靠对照测试抓出来）

🔧 四个真实 bug
  • 右移全归零：左移表与右移表写在同一个循环里，而右移要用到尚未填充的左移表项 → 所有右移结果变成 0。改成两遍初始化。由 12 万次随机棋盘对照测试抓出。
  • 搜索树读到脏棋盘：为省分配把棋盘放在全局变量上，但命中转置表时提前 return 却忘了恢复全局棋盘 → 调用方读到「上一个兄弟节点残留的棋盘」。 教训：用全局变量做棋盘时，所有 return 路径都必须先恢复状态。
  • 计分恒为 0：用「移动前后棋盘总和差」计分，但合并守恒（2+2=4 总和不变） → 必须让滑动函数返回本次合并得分并累加。
  • 全局空位缓冲被递归覆盖（见第五节）：不报错、不崩，只让棋力悄悄掉 8 倍。 教训：递归搜索里，跨递归复用的全局缓冲必须逐层快照。

九、本轮最大发现：转置表键冲突（此前结论更正）

旧报告第五节曾写「验证转置表 key 算术——无碰撞」。该结论有误。本轮用构造示例 + 20 万随机棋盘实证：
🔍 键冲突的构造与实证（experiments/_tt_collision_probe.js）
旧 key = depthTerm×2³² + lo×65536 + hi。hi 是完整 32 位（含 row2、row3）却按原值相加， lo×65536 又会跨过 2³² 边界，因此不同棋盘可映射到同一 key：
  • 构造示例：棋盘 A（仅 row3-col3 有 2，即 lo=0, hi=0x10000）与 棋盘 B（仅 row0-col3 有 2，即 lo=1, hi=0）→ key 完全相同（贡献都是 2¹⁶）。
  • 20 万随机真实感棋盘 @depth3：32 次跨棋盘首键冲突（0.02%）。
  • 影响：TT 偶发把 A 棋盘的搜索值错配给 B 棋盘，静默污染搜索（不报错、不崩）。

修复（_engine7_ttfix.js）：改用平坦类型数组 TT（nneonneo C++ 思路）—— K_LO/K_HI 两个 Uint32Array 精确存储 64 位键，TAG = depth×2+player， 开放寻址 + 线性探测（8 槽），每局 TAG.fill(0) 清表杜绝跨局污染，固定 ~33MB 内存。

240 局配对验证：棋力与 v7.1 统计持平（平均差 −46 ± 2,982，t=−0.02 不显著，胜率 51.2%）， 但吞吐 88.7 → 129 局/分（+45%）——Map 换类型数组本身就是一大速度红利。 结论：作为正确性修复采纳。

十一、四组实验的结论与解释

❌ 任务4 风险敏感 Expectimax：结构性失败（如实报告）
实现：value = mean − λ·risk，risk 为随机节点的下行半偏差 Σmax(0, mean−vᵢ)/n（含特征风险模式备选）， λ 扫了 0.005 / 0.01 / 0.05 / 0.1 / 0.2 共 5 个点（两个数量级），仅当 maxExp≥4096 启用以保护前期。

结果：全部配置 8192 达成率 15% → 0%，均分稳定掉到 44k 左右，且对 λ 几乎不敏感—— 这不是调参问题，而是结构性冲突：2048 从 4096→8192→16384 的每次升级都必须经历 「大块并排、蛇形临时破坏」的高波动过渡期。下行风险惩罚让 AI 系统性地回避这些押注局面， 稳定在 4096 后反复横跳（其 4096 达成率 81.7% 反而略高于基线）。结论：风险规避与「不押注就无法升级」的游戏结构直接冲突，不建议再沿此方向调参。 负面结果同样有价值：它证明基线的高方差不是缺陷，而是高阶突破的必要代价。
✅ 任务5 随机节点采样：现有分层抽样就是最优
  • 无重复分层抽样（基线）：均分 72,741 / 8192 率 15.0%。
  • 有放回均匀抽样：均分 34,319（−53%），早崩率 17.5%（×10）——重复分支浪费预算、坏运气覆盖不足，明确更差。
  • 按蛇形位置加权抽样：均分 56,352（−23%），8192 率 5.8%——对蛇头区域的偏置估计扭曲了期望值，也更差。

✅ 任务6 增量评价与动作排序：折叠表采纳，排序+memo 否决

  • 叶子评估 memo：与排序组合测试时无增益（叶子棋盘在兄弟 chance 分支间重复率低）。否决（保留为参数实验）。
  • 真正的提速空间在别处：TT 平坦化（+45%）与折叠表（+16.5%）合计让吞吐比旧基线提高 69%。

🎯 本轮最重要发现：8192→16384 失败模式的精确画像（96 局到达 8192 的游戏）
通过引擎内置里程碑诊断（首次达成步数/达成时空位/第二个 8192/死局结构），所有到达 8192 的游戏呈现完全一致的失败模式：
  • 0% 曾造出第二个 8192（60/60 与 36/36）——不是运气差，是结构性不可能；
  • 100% 死于最高 8192，无一局死时棋面有 16384；
  • 死局 0% 存在 exp≥12 的相邻同值对——到死都没把两个大方块并排过；
  • 首个 8192 后中位存活 ~1,700-1,900 步（不是猝死，是漫长的「原地踏步」后满盘）；
  • 死亡时中位空位 0（正常耗尽，非早崩）。

根因（尺度分析）：合并出第一个 8192 后，再造第二个 8192 需要在剩余 15 格重爬一条 4096 链。 但评价函数中 8192 主项 ≈ 2¹³×4.5¹⁵ ≈ 2.8×10¹⁴，而第二链 4096 项仅 ≈ 2¹²×4.5¹¹ ≈ 6×10¹⁰—— 只有主项的 0.02%。指数蛇形评价在结构上「看不见」第二链的发育，AI 的一切决策都被 8192 的保护项支配， 第二链永远排在次要地位直到满盘。这不是搜索深度问题（d7 终盘加深已验证），而是评价尺度问题。

📌 深度研究Ⅱ总结：16384 的结构性结论（3,900+ 局证据链）
本轮 1,200 局（F/G/H 批次）在 2,940 局基础上完成了一条完整的证据链：
  1. 诊断：到达 8192 的 96 局 100% 死于「第二链无法形成」——第二个 8192 出现率 0%、大方块相邻率 0%、 首个 8192 后平均存活 ~1,800 步仍原地踏步。
  2. 假说 1（评价可见性）：dualBase 双尺度重整让第二链权重提升 2000 倍 → 第二个 8192 出现率仍 0% → 排除。
  3. 假说 2（评价哲学）：after13nn 分段切换到 merges 主导的 nn 评价 → 8192 率减半 → 有害，排除。
  4. 假说 3（搜索深度）：终盘 d7 加深 → 稳定性显著改善（均分 +3.7%、2048 率 100%、早崩 0%）但 16384 仍 0% → 深度不是瓶颈。

结论：在「指数蛇形评价族 + depth≤7」框架内，16384 结构性不可达——8192 合并完成时的单链蛇形布局 在物理上已经排除第二条 4096 链的爬升空间，任何事后（post-8192）干预都无法挽回。 打破僵局需要在 4096→8192 合并之前就为双链布局，这本质上是一个价值函数学习问题 （N-Tuple/TD 从自我博弈中学习「什么样的 4096 局面能通向 16384」），而非手工权重的进一步调参。 这与 nneonneo 依赖 CMA-ES 大规模权重优化的经验一致。
本轮实际采纳：① 终盘加深 deepOnMaxExp=13（已移植进 _engine7_incremental.js）； ② 全展开+cprob 剪枝保留为 depth≥8 的使能技术（_engine7_prob.js）； ③ 诊断基础设施（diag 里程碑追踪 + _analyze_diag.js）为后续所有实验提供失败模式分析能力。
⚠️ 移植验证发现：终盘加深必须与预算配套（incd6deep，120 局配对）
把 deepOnMaxExp 移植回增量引擎后用 budget=45000 验证：均分 −4,279 ± 1,582（t=−2.71 显著更差，胜率 9.2%）。 原因：8192 后的 d7 搜索节点数超过 45k 预算 → 截断 → 静态评估代替深算，反而不如不加深。 对照组 probd6deep（同加深、budget=200k 无截断）+3,693 略优。 规则：deepOnMaxExp=13 必须搭配 budget ≥ 200,000；引擎已加注释。

🧱 新基础设施

🧪 训练调参记录（三轮教训，全部实证）
  1. 奖励尺度未归一化 → 发散：终局奖励 1e6 相对初始 V=0 巨大，权重撞满 clamp（|δ| 达 1e7）。修复：R = 合并得分/1000，B(16384)=1000、B(8192)=30。
  2. 决策局面 V + 1-ply spawn 期望选动作 → 策略无法自举：360 万局后仍是随机水平（均分 1125、120 步）。根因：V 弱时动作间的生成期望差异被噪声淹没，δ 收敛到随机策略的不动点。修复：改为 afterstate 值函数（V 定义在移动后/生成前，选动作直接比较 V(afterstate)，无生成噪声——文献标准）。
  3. max 算子过估计 × 大步长 → 发散：V(sA′) 取 max 引入系统性正偏差，α=0.05 时权重再次爆表。修复：每权重自适应步长 α_w = α0/(1 + visits·5e-4)（满足 Robbins-Monro 条件）+ clamp ±2000。

终版训练健康曲线（5 分钟 smoke 即见进步）：窗口均分 1975→2084 上升、512 占比 3.4%→4.4% 增长、|δ|≈0.44 稳定、max|w|≈1.4 远离 clamp、约 1800-2400 局/秒。正式训练 2 小时（约 8–12 百万局）进行中。
📉 批次 Q 快速实验（与训练同期）：两个负结果
  • C1 手工双链潜力项 wChain2（maxExp≥12 时对次链就绪度加分，3 万/6 万两档）：240 局结果与基线逐局完全相同——1e5 量级的加项在 1e14 的评价尺度下被分支间正常差异（1e9~1e12）完全淹没。再次证实：手工加性修正在指数蛇形评价体系内结构性无效，学习式融合（K 校准量级匹配）是唯一可行的注入方式。
  • C2 depth=7 全程（budget200k，60 局）：均分 79,893 / 8192 率 23.3% —— 弱于 d6（84,225 / 32.1%）。d6 是当前预算结构下的深度甜点；d7 的额外分支摊薄了每分支的预算，与 probd6 的教训一致。

📌 深度研究Ⅲ结论
做成了：完整的 N-Tuple/TD 基础设施（网络/训练器/融合引擎/42 项差分全 PASS）； afterstate TD(λ) + 自适应步长的训练管线健康收敛（自博弈均分 1,974→2,361+、512 占比持续上升、曲线上扬）； 侦察机制（30 局快评）在 30 分钟内捕获了「随机盘校准 K 错误」与「高位外推垃圾」两个关键问题。

没做成（如实）：中期权重的融合评估 4 档 K 全部有害——价值函数融合的价值上限受 V_td 自身质量硬性限制。 结合 C1（手工项被尺度淹没）与 C2（d7 不如 d6），第Ⅲ轮的最终结论： 当前框架内的低成本优化路线（手工修正项 / 浅 TD 融合 / 更深搜索）已全部穷尽。 16384 的剩余路径只剩两条重投入方向：
  1. 替换式 TD：6-tuple 网络（268MB）+ 数千万局级训练（10 小时+，文献标准配置），让 V_td 独立达到并超过手工评价水平后整体替换评价函数；
  2. CMA-ES 权重进化：对手工评价的全部参数做进化优化（每代 ~10 配置 × 96 局，数十代）——改变策略本身而非叠加修正。
训练器保留后台继续运行至 2 小时满（checkpoint 留档，供下轮长训练续训）。

🧬 B 线：6-tuple 替换式 TD（隔夜训练进行中）
_td_net.js 扩展 tupleType '6x8'（8 视图 × 16^6 = 512MB，行/列对称 6 元组 cell 表，24bit 索引组装）； 训练器双迹实现（4x8 平铺数组 / 6x8 Map）；_eval2.js 支持 --maxold（评估 20 进程 × 1280MB）。

训练稳定性攻坚（5 次启动的完整记录）：①α0=0.005 → 6-tuple 稀疏空间 visits 衰减慢， max 算子过估计累积（|δ|→2000，权重顶 clamp）；②α0=0.001 → 仍缓慢发散；③+时间衰减兜底 → 减速未根治； ④TD(0)+clamp±100 → 仍顶格；⑤终版：SARSA 化（on-policy target，无 max 算子）+ γ=0.999（封顶自引用状态的无界值）+ clamp ±30—— 数值稳定运行（|δ| 平台 ~42，策略均分缓升）。诊断关键：权重饱和槽是「全空列」自引用组合，γ=1 下值无界是数学必然。
